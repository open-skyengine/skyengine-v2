# ARM 平台与 EXT ABI

常见原生 MRP 模块面向 32 位 ARM，既可能含 ARM 指令，也可能含 Thumb 指令。兼容层面对的是 guest ABI，不是宿主机器 ABI：即使运行时本身编译为 64 位程序，MRP 地址、表项和模块参数仍通常是 32 位值。

## 指令集与字节序

- ARM 状态通常使用 32 位对齐指令；Thumb 状态使用 16/32 位编码。
- 函数指针最低位常用来表示 Thumb 状态：调用目标地址取清零 bit 0 后的值，同时切换执行状态。
- MTK 时代的常见样本使用小端 ARM。
- 历史 Spreadtrum 移植可能使用不同字节序或工具链约定，不能由 MRP 魔数推断全部 guest 数据的字节序。

容器字段的字节序与 EXT 指令/数据的字节序是两个问题。容器头大部分字段按小端读取，不意味着所有平台上的原生模块都必然小端。

**证据：多样本验证；Spreadtrum 差异为版本/平台相关。**

## 调用约定

常见模块遵循 AAPCS/APCS 风格的基本规则：

| 寄存器 | 常见用途 |
|---|---|
| R0-R3 | 前四个参数；R0 同时承载整数/指针返回值 |
| R4-R8 | 被调用者保存寄存器 |
| R9 | 平台寄存器或模块静态基址；MRP EXT 常用作 RW base |
| R10 | 被调用者保存寄存器；部分 helper 桩用于暂存外层静态基址 |
| R11 | 帧指针或通用的被调用者保存寄存器 |
| R12 | 调用内临时寄存器 |
| R13/SP | 栈指针 |
| R14/LR | 返回地址 |
| R15/PC | 程序计数器 |

超过四个的参数通常放到栈上。被调用者需按所用工具链约定保存 R4-R11 和 SP；ARM/Thumb 互调必须保留目标状态。结构体返回、64 位值和浮点参数可能依 SDK 编译选项产生额外规则，未经样本验证不应猜测。

**证据：稳定 SDK ABI（整数调用）；版本/平台相关（浮点及工具链扩展）。**

## R9、RW 与位置无关代码

历史 EXT 常以只读位置无关、可写位置无关方式链接。代码可以装载到不同地址，但对全局/静态可写数据的访问以模块 RW base 为中心，R9 常承担这个静态基址角色。

由此产生四条兼容要求：

1. 每个模块分别记录 RW base 和 RW 长度。
2. 进入模块前设置该模块的 R9；离开后恢复调用者 R9。
3. 平台函数回调 guest 时，使用被回调模块的寄存器上下文，而不是最近一次运行模块的上下文。
4. GOT 或静态重定位必须相对于所属模块处理，不能把 wrapper 的基址复用于 `game.ext` 或子模块。

有些 helper 包装桩使用 R10 临时保存外层 R9，但这是常见生成序列，不是要求所有二进制逐指令相同的格式规则。兼容器应实现寄存器语义，而不是匹配唯一的机器码模板。

**证据：稳定 SDK ABI（每模块 RW base）；常见约定（R10 的具体用途）。**

## `MRPGCMAP` 映像

多种原生文件的解压内容具有如下外形：

```text
+0x00  8 bytes  ASCII "MRPGCMAP"
+0x08  ...      可执行入口及模块映像
```

在观察样本中，`cfunction.ext`、`game.ext`、`graphics.ext`、`verdload.ext` 和 `mrc_loader.ext` 都出现过该标记。加载器应先检查文件至少有 8 字节并验证完整标记，再把入口候选设为 `base + 8`。随后仍需检查入口地址在可执行映射内、对齐和 ARM/Thumb 状态合法。

标记不是 ELF 头，也不描述完整段表。历史构建流程常从链接产物中提取平坦映像，再在前面添加该标记；RW 初始化和模块参数由入口/helper 协议补足。

**证据：多样本验证。** 不能仅凭扩展名假定存在标记；失败时应报告格式不支持。

## 入口与平台表

`MRPGCMAP` 后的入口通常为 `mr_c_function_load(int32_t code)`。模块通过入口附近的工具链约定取得平台函数表和参数地址，然后用[平台表槽 25](platform-table.md)登记真正处理生命周期的 helper。

平台表中的值也是 32 位 guest 值。表项可能是：

- 可调用函数地址；
- 变量本身的地址；
- 指向另一个表的地址；
- 保留的零值。

因此不能把所有槽位统一解释为函数。调用前还需要处理 Thumb bit；读写数据槽前需要验证目标地址和宽度。

## 栈与边界

guest 栈应满足工具链要求的对齐，并设置明确的可访问边界和保护区。进入未知模块前，兼容运行时应验证：

- PC/LR 处于可执行 guest 映射；
- SP 位于该线程或模块允许的栈范围；
- 平台表、参数块和 RW 范围完整映射；
- 所有由 guest 传给宿主的缓冲区都按长度重新验证；
- `address + length` 采用溢出检查，而不是先做 32 位加法。

固定 guest 虚拟地址、具体堆大小、屏幕缓冲位置和 JIT/解释器选择都不是 MRP ABI 的组成部分。实现可以自由选择，只要对 guest 呈现一致且受检查的 32 位地址空间。
