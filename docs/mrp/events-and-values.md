# 事件、按键与公共值

本页汇总常见 Mythroad SDK 在应用边界上使用的数值。数值名称便于描述 ABI；实现可使用不同的内部枚举，但送入 guest 的值必须保持一致。新增值和少数旧值的别名随 SDK 版本变化。

## 返回值

| 值 | 常见名称 | 含义 |
|---:|---|---|
| 0 | `MR_SUCCESS` | 操作成功 |
| -1 | `MR_FAILED` | 操作失败 |
| 1 | `MR_IGNORE` | 未处理或忽略 |
| 2 | `MR_WAITING` | 异步操作尚未完成 |

**证据：稳定 SDK ABI。** `MR_WAITING` 表示后续可能通过事件或回调完成，不能当作成功终态。

## 应用事件

| 值 | 名称 | 常见语义 |
|---:|---|---|
| 0 | `MR_KEY_PRESS` | 按键按下 |
| 1 | `MR_KEY_RELEASE` | 按键释放 |
| 2 | `MR_MOUSE_DOWN` | 指针/触摸按下 |
| 3 | `MR_MOUSE_UP` | 指针/触摸抬起 |
| 4 | `MR_MENU_SELECT` | 菜单选中 |
| 5 | `MR_MENU_RETURN` | 菜单返回 |
| 6 | `MR_DIALOG_EVENT` | 对话框事件 |
| 7 | `MR_SMS_INDICATION` | 短信到达；旧头文件也称 `MR_EVENT01` |
| 8 | `MR_EVENT_EXIT` | 系统请求退出 |
| 9 | `MR_SMS_RESULT` | 短信操作结果；旧头文件也称 `MR_EVENT02` |
| 10 | `MR_LOCALUI_EVENT` | 本地 UI 结果 |
| 11 | `MR_OSD_EVENT` | OSD/平台界面事件 |
| 12 | `MR_MOUSE_MOVE` | 指针/触摸移动 |
| 13 | `MR_ERROR_EVENT` | 异步错误 |
| 14 | `MR_PHB_EVENT` | 电话簿事件 |
| 15 | `MR_SMS_OP_EVENT` | 短信操作事件 |
| 16 | `MR_SMS_GET_SC` | 获取短信中心结果 |
| 17 | `MR_DATA_ACCOUNT_EVENT` | 数据账户选择结果 |
| 18 | `MR_MOTION_EVENT` | 运动/传感器事件 |

部分 SDK 还定义 `MR_TIMER_EVENT = 1001` 和 `MR_NET_EVENT = 1002`。另一些运行路径把计时器直接送到 native helper code 2，因此不能要求所有应用都收到 1001。

**证据：稳定 SDK ABI（0-18）；版本/平台相关（1001、1002 和旧别名）。**

## 按键编号

| 值 | 按键 | 值 | 按键 |
|---:|---|---:|---|
| 0 | 数字 0 | 12 | 上 |
| 1 | 数字 1 | 13 | 下 |
| 2 | 数字 2 | 14 | 左 |
| 3 | 数字 3 | 15 | 右 |
| 4 | 数字 4 | 16 | 电源/挂机 |
| 5 | 数字 5 | 17 | 左软键 |
| 6 | 数字 6 | 18 | 右软键 |
| 7 | 数字 7 | 19 | 呼叫/发送 |
| 8 | 数字 8 | 20 | 选择/确认 |
| 9 | 数字 9 | 21 | 音量加 |
| 10 | `*` | 22 | 音量减 |
| 11 | `#` | | |

较新或厂商定制头文件可能继续定义 clear、A、B、拍照等键。宿主应把未知实体键映射为明确的扩展值或不投递，而不应复用 0-22 的已有含义。

**证据：稳定 SDK ABI（0-22）；扩展键为版本/平台相关。**

## 文件打开标志

| 位值 | 常见含义 | 注意事项 |
|---:|---|---|
| 1 | 只读 | 与其他访问模式的组合应按 SDK 校验 |
| 2 | 只写 | - |
| 4 | 读写 | - |
| 8 | 创建 | 文件不存在时创建 |
| 16 | 共享打开或重新创建 | 不同 SDK 世代的名称和覆盖语义不同 |
| 32 | committed/立即提交 | 只在部分变体中出现 |

位 16 的差异会影响数据破坏风险。兼容层应根据目标 SDK 配置语义；在无法判定时，不应默认截断已有文件。

**证据：稳定 SDK ABI（低四位）；版本/平台相关（16、32）。**

## 事件投递约束

- `param0`、`param1` 是 32 位 ABI 值；只有事件定义明确要求时才将它们解释为 guest 地址。
- 按下和释放应保持顺序；暂停期间是否缓存输入属于版本策略，但恢复后不得制造无对应按下的释放事件。
- 指针坐标应先映射到 guest 画布，再投递，避免把宿主窗口缩放坐标泄漏给应用。
- 网络、短信和平台 UI 的异步结果应关联仍然存活的模块；模块退出后不得回调已释放的 helper。
- 事件值未知时应保留原值用于诊断，不能数组越界或误派发为其他事件。
