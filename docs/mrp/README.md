# MRP 兼容性资料

本目录记录 Mythroad/MRP 程序为了互操作而必须遵守的文件格式、启动流程和二进制接口。文档采用重新组织、重新表述的方式编写；它描述的是可由二进制样本、SDK 接口和跨样本行为验证的技术事实，不移植任何现有运行时的源码实现。

## 阅读顺序

1. [容器格式](container-format.md)：MRP 头部、目录、数据记录和压缩方式。
2. [执行模型](execution-model.md)：`start.mr`、`cfunction.ext`、`game.ext` 以及事件循环之间的关系。
3. [ARM ABI](arm-abi.md)：ARM/Thumb、寄存器约定、静态基址和 `MRPGCMAP`。
4. [平台表](platform-table.md)：一套广泛使用的 150 槽 Mythroad 平台 ABI。
5. [事件与常量](events-and-values.md)：返回值、事件、按键和文件打开标志。

## 证据等级

文中使用以下标签限定结论的适用范围：

| 标签 | 含义 |
|---|---|
| **多样本验证** | 已在多个独立 MRP 包中观察到相同布局或行为 |
| **稳定 SDK ABI** | 是本机模块与宿主交换数据时必须一致的名称、序号或调用约定 |
| **常见约定** | 在常见工具链和程序中成立，但不应当作为解析器的唯一输入 |
| **版本/平台相关** | 不同 SDK 世代、芯片平台或厂商移植可能不同 |
| **有限样本观察** | 目前证据不足，兼容实现应保留探测或失败路径 |

没有标签的概述段落，应结合其所链接章节中的具体标签理解。

## 兼容性边界

本目录以新写的文字记录功能事实、为了兼容必须识别的数值槽位、接口名称以及实测二进制布局，只给出理解接口所需的最小声明，不规定内部类设计、内存地址、线程模型、解释器选型或错误恢复算法。

以下内容不应混为一谈：

- **MRP 互操作事实**：魔数、字段偏移、目录编码、入口协议、寄存器和平台表槽位。
- **项目实现选择**：虚拟地址、宿主对象模型、缓存策略、特定游戏补丁以及未被 ABI 要求的兼容技巧。
- **受独立权利约束的材料**：具体实现源码、文档的原始表达、MRP 包内的程序、美术、声音和字体。

因此，换用 Rust、C 或其他语言本身并不能自动改变许可结论。独立重写时仍应保留需求和测试的来源记录，只实现互操作所必需的行为，并避免复制原项目具有创造性的源码结构、注释和实现表达。具体分发是否满足许可证及当地法律，需要结合代码来源和开发过程判断；这里是工程边界说明，不是法律意见。

## 兼容实现的最低要求

一个读取不可信 MRP 文件的实现至少应当：

- 先验证整数加法、文件范围和分配上限，再读取或解压数据；
- 不假设目录名唯一、字符串一定以 NUL 结尾或所有包都使用 gzip；
- 不把 32 位 guest 指针直接当作宿主指针；
- 根据模块分别保存静态基址，跨模块调用时恢复寄存器上下文；
- 在调用平台表槽位前验证所支持的 ABI 版本和表长度；
- 对未实现、保留和平台相关的功能给出确定且可诊断的失败结果。
